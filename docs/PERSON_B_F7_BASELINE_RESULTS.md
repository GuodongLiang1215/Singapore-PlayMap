## 可以确认的问题

1. **细分类丢失**：s02、s06 的解释记录了 restaurant，但检索命令缺少对应关键词。本地检查拒绝这类输出，避免把所有餐饮都当成餐厅。
2. **引用与结构错误**：s11、s32 出现空 quote；s30、m07 的非操作分段缺少必需的 name。provider schema 当前只强制 type/quote，部分重要字段仍靠提示词约定。
3. **时段与营业条件**：s01、s08、s31、s35、s39 等输出未完整遵循未知状态和澄清规则，第四尺度分数尤其低。空间 anchor 被误放入 place.query 也会把附近查询变成指定地点搜索。
4. **本地误拒**：s03 的 park/nature 已有领域别名，但一致性检查没有复用；s36 的 departure_at、m08 的 transport_mode 有对应可执行字段，却仍进入不支持分支。应修检查器，不能把这些全部归罪于模型。
5. **记忆与作用范围**：m10 把替换站点误标成 visit:new；另一轮 restaurant 关键词又被丢掉。固定 ID 绑定能解决正确解析后的调序记忆，不能修复模型先把作用范围标错的问题。
6. **标注与合理分法**：有的模型把无障碍和无台阶拆成两个单元，而标注合成一个；有的 park 用 place_type 而标注用 category。严格 F1 会扣分，这些需要人工判断，不能全部解释成语义理解失败。
