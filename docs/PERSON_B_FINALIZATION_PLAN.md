## 6. 输入/输出文档的具体结构

正式文档必须区分以下四层；不能把一个“通用JSON”同时当作所有接口格式：

| 层 | 输入 | 输出 | 谁负责 |
|---|---|---|---|
| 浏览器↔B API | ChatRequest：原话、Draft、Preferences、Pending、session/revision、consent、可选证据引用 | 提案 ticket、slots、preview、解释、版本与调用诊断 | 前端传状态，B 校验并返回提案；chat 不自动采用 |
| 模型协议 | INTERPRET 的精简已采用上下文/待确认请求；SELECT 的真实候选及适用偏好 | 严格 semantic_segments + commands；或 picks | 模型只能提出意图和选择，不能写可信核验结论或坐标 |
| B 内部表示 | 编译后的 actions、绑定后的要求、候选槽 | 同一次待采用 Draft/Preferences、阻断项和逐要求处理结果 | 确定性代码负责转换、合并、范围和一致性校验 |
| 采用/交接 | resolve 的 ticket、session/revision、choices | 可由客户端应用的 Draft/Preferences；ready_to_calculate 等阶段信号 | resolve 返回结果；前端实际采用；规划器负责后续计算 |

字段表至少包含：字段路径、类型、必填/可省略、null语义、单位/界限、用途与必要性、允许的 scope、写入方、来源、能力状态、失败行为、兼容方式、代码位置。引用现有模型/schema，避免另外手写一套会漂移的定义。

特别写清：

- `visit:N`、`visit:new:N` 是模型当前快照引用；`visit_id:ID` 是本地持久身份。`target_position` 不是永久ID。
- `selected_key`、`can_apply`、`ready_to_calculate`、`satisfied` 各自表示什么；模型预选不等于用户确认，能计算不等于现实可行。
- 未提供、显式null、清空、false、0分钟及未知值的区别；集合成员删除不能等同整组清空。
- ticket、verification_ref、message turn 与 revision 的不同用途、作用范围和寿命。
- 五大类与细类的关系；来源细类、search_tags、距离带、建议时长、营业参考各能证明什么。
- 哪些原话/公开名称发送给模型，哪些坐标留本地；专名查询可能单独发送 OneMap。一般聊天最多两次模型调用，解释实验每轮一次，两者不能混报。
- 当前待确认票据和核验记录是有界短期 RAM；Preferences 随客户端往返，并非已实现长期用户记忆数据库。[票据](../app/stage2c/engine.py#L76)、[模型](../app/stage2c/models.py#L140)。

正式示例至少覆盖：查询咖啡馆、两站不同局部偏好、替换并外带、只改停留、仅撤一个集合成员、Pending追问后确认、取消、冲突/未知/未支持、过期ticket。每例同时给输入、输出关键字段、采用前后状态和不可作出的事实保证。

## 7. 接口文档的具体结构

当前接口清单来自 [api.py](../app/stage2c/api.py)，不能把 C 的分支接口写成 B 现有接口：

| 接口 | 作用 | 必须说明的限制 |
|---|---|---|
| `GET /api/stage2c/status` | 配置可读、协议版本、能力及调用上限 | configured不代表真实调用成功，不触发模型探测 |
| `POST /api/stage2c/chat` | 解释、检索、选择、形成提案 | 最多两次模型调用；不自动采用；错误保留原状态；地图专名查询另计 |
| `POST /api/stage2c/resolve` | 校验票据和候选，返回可采用结果 | 模型调用为0；客户端仍需应用；不是路线可行性结果 |
| `POST /api/stage2c/verification` | 读取当前证据引用并恢复覆盖范围内的状态 | 模型调用为0；过期/换快照/目录变化降为未知；不是新路线搜索 |
| `POST /api/stage2c/forget` | 清理本会话后端短期提案、轮次和核验记录 | 不代表删除服务商数据，也不自动替前端清理所有状态 |

每个接口要写：请求/响应示例，必填字段与界限，HTTP状态码与稳定错误码，能否改变已采用状态，是否调用模型/地图服务，客户端下一步动作，过期/重试/并发规则及真实代码入口。对错误和取消说明“已经发出的请求可能仍计入费用”，不承诺自动重试。

后续 C 集成单列：`/recommend-nearby` 的 `max_travel_minutes`、`/alternatives` 的全路线候选验证，以及 café 等细类和局部约束的传递需求。这里只记录对接点和未完成状态，不实现，也不把它列为本次B验收前置。
